# The language

A syntactic subset of yel ([LANGUAGE.md](https://github.com/szkabaroli/yel/blob/main/LANGUAGE.md)), as yel2 compiles it today:

- **Packages and modules,** in two layers, as WIT has them (a package, and interfaces in it):
  - a package is a directory of `.yel` files (or one file). Its files share one set of names, and name it `package ns:name;` when another package includes it. The compiler's input is a package;
  - a module is one layer of names inside a package, `module api { … }`, holding funcs and types. A module holds no module. Within its package a module is reached by its name, `api.render(x)` or `api.Point`, from any file;
  - another package reaches a module by including it: `from "ns:name" include api, theme as look;` (or `from "ns:name/api" include api;`, or a path, `from "./ui" include api;`). A package id is looked for as a directory `name` beside the including package, then in each `-I` directory. Only modules are included, so another package's top level stays its own, and packages cannot include each other;
  - a reactor's (no `main`) visible modules are its WIT exports (next), and `@(private)` keeps one in; there is no `export` keyword. `extern module` waits for WIT imports;
  - every item has a key, unique in the program: `lex`, `lexer.lex`, `yel:ui/api.render` (in C, `u_lexer__lex`). A bare case needs no `Type.` where its variant is expected.
- **WIT, as modules.** `from "wasi:cli" include environment;` makes a WIT interface a module (`environment.get-environment()`): its types are yel's records, variants, enums, flags and resources, its funcs a component's imports. WIT packages are read from `runtime/wit` (WASI 0.3.0, from wasmtime-wasi) and each `-I` directory. A reactor (a program without `main`) exports its visible modules: each module of its own package not marked `@(private)` is a WIT interface of its visible funcs, the component's exports (a command, with `main`, exports none: its modules are its own). The canonical ABI is yelc's own (no wit-bindgen): each type's canonical layout is a C struct, helpers made for each type lower yel values into it and lift them out (onto the heap, rooted while made), and flat values go through uint64 slots, a variant's joined places as bits. `--wit <dir>` writes the component's WIT world, for wasi-sdk's `--target=wasm32-wasip3 -Wl,--component-type,<dir>`; `wasmtime run -W component-model-async=y -S p3=y` runs it (`--invoke 'f(...)'` calls an export with WAVE). An export's post-return is a turn's end, where the collector may run. Natively the same code runs against C in the runtime (`runtime/wasi-native.h`: the environment, random, the clocks, the working directory as a preopen, the terminals, TCP sockets, name lookup: `ip-name-lookup`'s `resolve-addresses`, the system's resolver on libuv's thread pool), and an import it has not is a C `#error` in a native build. A resource's value is its handle, a `u32` in C on both targets and never on the heap: its static funcs and constructor (`new`) are called on the type (`types.tcp-socket.create(family)`), its methods on a handle (`s.bind(address)`, found by the handle's type), and `s.drop()` gives it back. The host owns what a handle names: in a component the component's host, natively a table in `wasi-native.h` (a handle to a file descriptor, a socket). Nothing drops a handle but `drop` (the collector never does), and a handle given where the WIT says `own` is the callee's. A func whose types name what is not known is left out of a WIT interface (a call of it says so), and so are resources a program exports.
- **Functions:** top-level funcs, in yel's member syntax: `name: func(a: s32, b: string,) -> s32 { … }`. `main(args: list<string>)` is the entry point, and its value is the exit code.
- **Closures:** `{ params -> body }` (`{ p -> p.age > limit }`, `{ x: s32, y: s32 -> x + y }`), or a block where a func of no params is wanted (`let on-click: func() = { clicks += 1; };`). A param's type is the wanted func's where one is wanted (`people.filter({ p -> … })`), else written. A closure captures by reference: it and the scope it is made in share each variable (`let add = { n: s32 -> total += n; };` changes `total`), a variable outlives its scope while a closure holds it, and each turn of a `for` or a `loop` has its own (a closure made in a turn keeps that turn's item or bindings). `return` in a closure returns from it, and `break` and `continue` do not cross it. Any expression's func value is called with `(…)` (`greets[i]()`, `make()()`); `x.f(…)` is always a func's call. The captured variables of one unit (a func's, a closure's or a `for`'s body; a `for`'s, each turn) live in one environment, a record the closures made in it share, linked to the one around it; a variable no closure captures stays a C local. A func value is its C function and its environment (`{ fn, env }`, NULL for a top-level func's, called through an adapter), so a call of a named func pays nothing. An environment whose closures stay in the func (given `filter`, `sort`, `apply`) is on the stack, not the heap.
- **Conversions:** `x as T`, between numbers, chars and bools, each defined (no C undefined behaviour): an integer to an integer wraps (two's complement); to a float, the nearest; a float to an integer saturates, NaN to 0, toward zero; f64 to f32 rounds, past f32's range an infinity; a `bool` to an integer is 0 or 1, a `char` its code point; an integer to a `char` is that scalar value, U+FFFD where it is none (a surrogate, past U+10FFFF). A float or a `char` comes from nothing else, and nothing converts to a `bool`. `as` binds tighter than `*` and `+` and looser than `-` (`a + b as s64` is `a + (b as s64)`, `-x as s64` is `(-x) as s64`), and an unsettled literal takes `T` (`1 as s64` is an `s64`, `200 as s8` out of its range).
- **Funcs as values:** a top-level func's name, not called, is a value of type `func(T, U) -> R` (a C function pointer: it captures nothing, so no closure yet). Pass it (`sort(xs, by-score)`), keep it in a variable, a record or a list, and call it as any func (`less(a, b)`, a local's name first). Calling `x.f()` is always a func's, never a local's. A generic func or an extern is no value yet, and WIT has no func type, so none crosses a component's boundary.
- **The standard library** (`runtime/std`; its core, the package `yel:std`, in `runtime/std/core`: its folders `text`, `collections`, `numbers`, `async`, `reactive`, `runtime` and `host` one package) is written in yel over the prelude's externs, one file for each part: `text` (`len`, a string's bytes; `find`, `split`, `trim`, `replace`, `lines`, `starts-with`, `to-upper`, `pad-start`, …; `bytes`, `chars`, `is-utf8`, and `string-from`, bytes made a string with their UTF-8 checked), `buffer` (bytes gathered, append-only: `buffer(capacity)`, `push`, `push-byte`, `push-char`, `push-bytes`, `len`, `to-string` sharing its bytes, `to-bytes` a copy; the std's strings are made in one, one allocation each), `list` (`index-of`, `sort` with an order given as a func, `filter`, `map`, `any`, `all`), `char` (`is-digit`, `is-space`, …) and `number` (`parse-int`, `parse-unsigned`, each with a `-radix` form, and `parse-float`: the whole text or none), and `integer` (each integer type's bounds in a module of its name: `u32.MAX`, `s64.MIN`, of that type). A program reaches its names without an include, after its own and the prelude's, so a func a program names the same is the one it calls. Calls are uniform (`s.trim()` is `trim(s)`; a module's funcs that take its own type first are that type's methods wherever it goes, before the prelude's and the library's of that name: `b.component(…)` is `std:build`'s on its `builder`), and where the prelude and the library have a name more than once (`len`, `push`, `to-string`, `contains`, `slice`, `reverse`) the first argument's type chooses (`"abc".len()`, `xs.len()`, `b.len()`), one taking that type itself before one taking any type (`T`); a first argument whose type is not known yet is an error that asks for an annotation. A string is bytes, UTF-8 by convention, and a slice of it shares its bytes; a `buffer` is no WIT type (at a component's boundary, give its `to-string()` or `to-bytes()`). A function no program calls is dropped, so a program carries only what it uses. Those files are std's core, what the language needs (what the compiler lowers syntax to, and the methods of its own types). The rest of the library is optional, a package in each other directory of `runtime/std`, reached only by an include: `from "std:encoding/json" include json;` (`json.parse`, `json.write`, `json.value`). `std:encoding` has `json`, `hex`, `base32` and `base64` (RFC 4648; base64's URL alphabet too, `encode-url`), and `uuid` (RFC 9562: `uuid.random()` version 4, `uuid.time-ordered()` version 7, ordered within a millisecond by RFC 9562's counter, `parse`, `to-string`, `bytes`). `std:url` is the WHATWG URL Standard's URLs: `url.parse(text)` (a scheme, user, password, host, port, path, query, fragment, each percent-encoded as its part needs, `.` and `..` segments taken out, a special scheme's default port left out), `url.join(base, reference)`, `url.write`, `url.origin`, a query's `params` and `param`, `query` (a form's: a space a `+`), `encode` and `decode` (a component's); an international host (Punycode) and IP address normalising are not here. `std:time` is time as `wasi:clocks` and Unix count it: `time.now()`, an `instant` (seconds and nanoseconds since 1970), a `duration` (shown as Go shows one, `1h2m3.5s`), the calendar (`to-date-time(instant, offset)` and back, `weekday`, `day-of-year`), ISO 8601 / RFC 3339 written (`to-iso`; `format`: an offset kept) and read (`parse`: `Z`, `±HH:MM`, a date alone; strict, where `Date.parse` rolls `2026-02-30` over); time zones past a fixed offset are not (WASI's timezone interface is not in hosts yet). `tests/url.yel` and `tests/time.yel` check them against outputs worked out apart from yel. A `std:<name>` with no directory there is WASI's `wasi:<name>`, so a program names the system's interfaces as std's too (`std:cli`, `std:filesystem`); a library is never named as a WASI package is.
- **C:** yel's `extern` with an attribute, like `@primitive`: `@c(name = "yel_bytes_len") len: extern func(s: string) -> s32;`. Compiled code calls that C function directly, with C types (`ystr`, `int32_t`). A generic extern, `func<T>`, is a C macro that takes each type argument's C type first.
- **Records and resources:** two kinds of declared type with fields, which differ in what a name of one holds, and so in how each crosses WIT:
  - `record Point { x: s32, y: s32, }` is a value: copied where it goes (a variable, a field, a parameter, a list's item; a C struct in place, never on the heap by itself), equal by its fields (and so a map's key by them), its own type (two records of the same fields are two types). A field is set where the record is: `p.x = 3;` on a variable, `line.to.y = 1;` on a field of one, `canvas.cursor.x = 5;` on a resource's field; on a copy (`make().x = 1`, a list's item read) it is an error, as it would change nothing. It holds itself only behind a pointer (a list, a variant's case, a resource), never in place (an option, a tuple, a fixed list: its size would never end). It crosses WIT as a WIT `record`, copied, its fields in declared order; a WIT record is one. A global of one starts as its fields' zero values.
  - `resource Canvas { cursor: Point, lines: list<Line>, }` is a shared object: one object on the heap, every name of it sees what another changes (`same.cursor.y = 6`), equal only to itself, and it may hold itself (a tree, a list of cells). A variant holds its state where its state has cases (`resource Connection { state: ConnectionState }`, a field assigned in place). It crosses WIT as a WIT resource, a handle, never a copy (which would lose what makes it one): a reactor exports each resource one of its visible modules declares, as that module's WIT interface's `resource`. Its constructor is the module's `new` giving one (`[constructor]`), its methods the module's funcs taking it first as `self` (`[method]counter.bump`: `c.bump(2)` on the other side), and `drop: func(self: R)`, where there is one, runs when the host drops a handle (`[dtor]`). A result of one is an own handle (`[resource-new]` of a rep: a slot of the resource's table, which the runtime keeps and the collector marks, so what the host holds stays alive), a parameter a borrowed one (its rep names the object). It crosses only in its own module's funcs, else the error says so. An imported WIT resource is one whose fields are the host's (its funcs called on its handle). `tests/res-api` exports one and `tests/res-caller` imports it, the two plugged together (`wac plug`).
  - Literals `{ x: 1, y: 2, }`, field reads `p.x`, field writes `p.x = 3;` or `p.y += 1;`, record patterns, and functions taking one first (`p.move(1)`) are the same for both. A literal is one where it is wanted (a typed `let`, a parameter, a field, a result, the one record of a wanted union with its fields); anywhere else it is an anonymous record (no record is chosen by its fields: declaring one never changes what a literal elsewhere is).
- **Observable resources:** `@(observable) resource Profile { id: u32, items: list<string>, @(ignored) log: list<string>, }` tells std's `observe` (`runtime/std/core/reactive/observe.yel`) of each read and each write of its fields, from wherever they are, so what a run of code read is known exactly, its conditions too. The compiler's half is the hooks: the resource holds a registrar (`observe.Registrar`, its last field, made with it; no program names it and none shows it), a read of a field calls `observe.access(registrar, field)` before it, and a write `observe.will-set(registrar, field)`: the field assigned (`p.id = 2`, `p.id += 1`), a part of a value in it (`p.at.x = 5`, a fixed list's item), and a list or a map in it given a call that may change it (`p.items.push(x)`, `p.items[0] = x`, a func of yours that writes it: the program's flow says which calls do, so `p.items.len()` and a func that only reads it tell nothing, nor one that writes only through an `@(observable)` resource in it, `p.sheets.map({ s -> s.name })` or a closure renaming each, since that resource tells of its own fields: `escape.yel`'s `param-changes`). A change made through another name for that list (`let xs = p.items; xs.push(x)`) is not seen: write through the field. `@(ignored)` leaves a field out (no hooks), and `@(observable)` goes on a resource only (a record is a value: no one shares it to see it change). Attributes combine, `@(private, observable)`. std's half is yel: `observe.track(apply, on-change)` runs `apply`, keeping what it read (a global holds the reads while it runs: `access` is one test of it when nothing is tracked), and calls `on-change` once, on the first change to any of it (its watch is then done; `rearm` watches again, `changed` says whether any of it has changed since, `untracked` runs a func whose reads are kept by no one). `reactive` (`runtime/std/core/reactive/reactive.yel`) is made of it: `reactive.effect(run)` runs `run` now and, after a `reactive.flush()`, again each time what it read has changed (several changes, one run; what `run` gives back is its cleanup, run before it runs again and when it is let go); the effects made while it runs are its own, let go before it runs again; `reactive.within(owner, run)` puts what is made in an owner, which `reactive.dispose(owner)` lets go (a component's, once unmounted); `reactive.batch(run)` runs and then flushes; a flush that keeps finding work after 100 rounds is an update loop, and stops the program saying so. `tests/observable.yel` shows each; `tests/observable-async.yel` fills observable state from async work: an effect starts a load when an id changes (a run count drops a result no longer wanted) and opens a stream for it (the old one let go), and the tasks write the state and flush.
- **Views:** `view Counter { … }` in a module is a UI view, the module its WIT interface (one view to a module): its fields (`name: string = "ada";`, each a prop with a `get-` and a `set-`, but those `@(private)`; one `@(mount)` is also given to `mount`, after the root, and set before the tree is first built, as the shell's `mount(root, intent)` gives a page where it opens), then one element, the host's (`yel:ui`'s `dom`: the package includes it, `from "yel:ui" include dom;`). An element is `Tag { items }`, `Tag` a widget: an element the host draws, declared by a widget set (`widget Button { variant: "default" | "ghost"; disabled: bool; on.click: func(click-event); }`, `@(container)` on one that takes items, `@(container(Tab))` on a compound that holds only its parts, directly or through an `if` or a `for`; `widget Button: Element { … }` has its bases' fields too, each a widget of its module in that file, `@(base)` on one drawn by none; its attributes are what the host takes, a string, strings, bool, s32, f64 or `dom.color`, its events `on.` and what the host sends, so a handler's parameter is typed by it and its body runs for that case only, or, a closure that takes none, whatever the event carries). A view names a widget bare, from a set its file includes or its package declares (`from "yel:widgets" include meshx;`); each widget is funcs of its module, `widget-Button-make`, `-set-` and `-as-` for each attribute, `-on-`/`-when-` for each event, `-container`, which the checker finds through the modules in scope, so a widget, an attribute or an event that is not there, an attribute of another type or items in a widget that is no container, is an error where it is written. A widget set's module is no interface of a component. `yel:widgets` is generated (meshx-shell's `scripts/generate-yel-widgets.mjs`): `html` (`html.yel`), every element of the HTML standard and each its attributes, as the standard has them, `HTMLElement` their base with the global ones and every element its own (MDN's browser-compat-data, from the standard: none deprecated, none outside it; `input`'s `type` one of its kinds): a trusted host draws them all, the sandboxed one only yel-protocol's tag specs (each other element says so) with yel-host's allowlist's attributes; and `meshx` (`meshx.yel`), the host's widgets (yel-core's tags, yel-solid's prop types, shell-next's registry for a compound's parts), what most of them take declared once, by its `Element`; `examples/widgets` is its copy. An element's items are text (`"Clicked {count} times"`), elements, attributes (`weight: "bold"`, a style `style.pad: 8.0`, its name the vocabulary's, dotted where it nests: `style.pad.x: 400`, `style.overflow.y: "auto"`; a `string`, `bool`, `s32`, `f64` or `dom.color`), handlers, each an `on.` attribute given a closure (`on.click: { -> count += 1; }`, as `style.` names a style; what the event carries, its parameter: `on.input: { change: input-change -> text = change.value; }`, its body run for that case of std's `event-payload` only, a parameter with no type the whole `event-payload`), `if cond { items } else { items }` (`else if` too) and `for item in items key(item) { items }` (a row for each item, kept by its key: one made for a new key where it goes, one let go for a key gone, the rest kept, each given its item when it changes: the row reads it through a getter, so only what read it is told; the rows whose old places run in order stay put, std's `view-nodes.in-place`, and only the others move, each whole: what an `if` or a `for` in it shows goes with it). An element whose tag is another view's, `module.View { name: value }` (one view to a module, so another is always named by its module), is that view in this one's tree: made, given its props (each a field of it, but those `@(private)`; one that reads what changes kept current, so only what reads it in the child is told), its tree put where the element goes, and let go with the branch, row or view it is in (its nodes removed with it). A view's callback is a prop of a func's type, declared `on.` (`on.pick: func(string);`: one none is given does nothing, so it needs no value to start with; a func's type and `on.` go together), called in the view as `on.pick(name)` (no `get-`/`set-` in its WIT: a func is no WIT value), and given as a host element's handler is, a closure (`on.pick: { key -> chosen = key; }`), once: what it reads, read when it is called. `on.pick` names the event `pick` (the host's `click`, a view's `pick`); a field of a view holds it as `on-pick`. A view a component does not export as an interface goes in a module it does not export (`@(private) module`). Each view has, for that, `view-build`, `view-release` and a `view-set-` for each prop, its package's own (not in its WIT). The view's fields are named bare in it (`count`, `count += 1`: the view's), and nothing in it is named as one (a local, a parameter, a for's variable). `view` is a keyword only there (`view Name {` beginning a declaration). A view is lowered by `lower.yel` (`lower.lower-view`) to nodes, its own expressions in place: an `@(observable)` resource of its fields, and `new`, `mount(root)`, `unmount`, `dispatch(handler-id, payload)` and each prop's `get-`/`set-`, the WIT a host takes (every yel guest's: `event-payload` and its records, `click-event`, `selection`, `drop-event`, `key-event`, `input-change`, `clipboard-data`, `grid-cell`, `grid-range`, are defined in the view's interface, as `apps/cloud`'s WIT declares them). `mount` makes the tree under an owner `unmount` lets go; text or an attribute that reads a field is kept current by `std/reactive`'s `watch` (set again when what it read changes, only where the value differs); an `if` or a `for` an effect over an anchor (a comment node) whose branch or rows are made under owners of their own (what they made let go with them); a handler is `std/view-events`' (by id, from 1, let go with its owner: `owned-handler`), run by `dispatch`, which then flushes; a prop set flushes too. So a click tells the host only what changed (`setTextContent` of the one text). An effect made in another's run runs after it in a flush (the outermost first), so a branch an outer `if` lets go is never updated on the way. `tests/view` runs views natively against a `dom` module that prints each op. `examples/` holds views built as the shell's hosts take them (`examples/build.sh [name …]`, `WASI_SDK` set: each `examples/<name>/build/<name>.wasm`, `yel:ui/dom` from `examples/wit`): `hello` (yel-solid's hello), `todo` (an input, Enter to add, a keyed row for each task with a checkbox and a remove button), `settings` (tabs choosing a panel, switches) and `search` (a list filtered as it is typed, Escape to clear).
- **Anonymous records:** `{ x: s32, y: s32 }` is a type, a record by its fields: one set of fields is one type, in any order (they are kept in order of their names), `type point = { x: s32, y: s32 };` names it, and `let a = { x: 1, y: 2, };` makes one. It is a value (a C struct copied where it goes, never on the heap by itself), so its fields are read, never assigned: a new one is made. Record patterns match it (`{ x: 0 }`, `let { x, y }`), and `...rest` in a record pattern binds the fields not named as one (`let { name, ...rest } = person;` gives `rest: { age: s32, city: string }`, from a declared record too). Its alias crosses WIT as a WIT record (fields in that order).
- **`T & readonly`:** values no one writes through this type, deep (a readonly list's items, a readonly record's fields and a readonly variant's payloads read readonly too); numbers, strings and the like are readonly already. Held exactly as `T` (nothing in the C). A literal is readonly where that is wanted (`let xs: list<string> & readonly = ["a"];`, its parts checked readonly too), and a func can give one back. Writing through one is an error when compiling: a field assigned, or a func that writes it (`push`, `xs[i] = …`, or a func of yours that does, through any local). What each func does with its parameters (writes, keeps where it may be written, gives back) is worked out from its body by the program's flow on the IR (`compiler/escape.yel`, a fixpoint over the funcs; an extern's from its declaration, below), so a readonly value goes to any parameter its func only reads (`longest(fixed)` with `longest: func(xs: list<string>)`), and a mutable value to a readonly parameter its func never keeps or gives back. A value becomes readonly without a copy where no other name has it: a literal, a func's result when everything the func gives back is new (a literal, such a func's result, or a local made so: worked out from its body, so `evens(9)` with `evens: func(n: s32) -> list<s32>` is readonly where that is wanted), or a local everything given is new, never kept (stored, captured) nor given another name, and not used after it is made readonly (it is moved: build a list with `push`, then `let frozen: list<string> & readonly = words;` and use `frozen`), nor made readonly in a loop it was made outside of. The same lets a value be given a readonly parameter its func keeps (it is given away). Otherwise the error says why (`words is used again at 6:5`, `b is another name for a`, `pick may give back a value another name has`). Readonly lists are covariant where their items are held one way (`list<"a"> & readonly` is a `list<string> & readonly`). A generic func gives a readonly argument back only where its result's type, its type arguments given, is readonly (or holds nothing that is written: a number, an option of one). A started call's readonly parameter holds its argument while the task runs, so a mutable value given one must be one no other name has; and one call may not give a value readonly and also to another argument that may write it (`show(live, live)`: the readonly one would see it change). One flow serves every analysis: `compiler/escape.yel`, on the IR, groups the locals that may hold one value (a union-find) and says of each group whether it escapes (stored, kept by a func it is given, captured), is given back, is written, may hold a value made elsewhere (a parameter's, a field's, a result that is not new), or is moved to the host; each func's summary (which parameters it writes, keeps, gives back; whether its result is new) is a fixpoint over the program (`flow.fixpoint`). Records stay on the stack by it, the host's ends are let go by it (`compiler/releases.yel`), and the readonly and move checks (`compiler/effects.yel`, after codegen) read it, with where each local is used read from the syntax tree. What an extern does is derived from its declaration (`flow.derive`): a parameter written `& readonly` is only read, a result may hold a parameter whose type shares a part with its type (`map-keys(m: map<K, V>) -> list<K>`), a parameter may be kept in another it may write that can hold it (`push(xs: list<T>, v: T)`), and what types cannot say is `@c(keeps = "f", gives = "s")` (the executor keeping a task, a stream's own items); a WIT func's are copied across (streams and futures moved), its results new. IR locals know their binding and IR nodes their source span, so what is found there is said where the program is. These analyses (readonly, moves, the host ends let go) know a local by its binding, not its name: the checker records which binding each name read and assigned is (`Func.bindings`, by each `let`'s, pattern name's, `for`'s and parameter's `Mark`), and each IR local the binding it is, so another binding of the same name (a shadowing `let`, an arm's) is another local. They walk the tree with `compiler/walk.yel`'s generators (`exprs`, `stmts`, `tree`).
- **Variants and enums:** `variant Shape { dot, circle(s32), }` and `enum Color { red, green, }`. Construct with `Shape.circle(2)` or `Color.red`. `option` is built in as `some(x)` and `none`, and `result` as `ok(x)` and `err(e)` (bare `ok` or `err` when that side has no payload).
- **Flags:** `flags Access { read, write, }`. `Access.read | Access.write` combines them (with `&` and `^`), and `granted.write` reads one as a `bool`.
- **Fixed-length lists:** `list<T, N>` is WIT's fixed-length list: N items held by value (a C struct of an array, never on the heap), copied where given, and laid out inline across a component boundary (`wasmtime -W component-model-fixed-length-lists=y`). `let v: list<s32, 3> = [1, 2, 3];` makes one (a literal of that many items, where one is wanted), and `list<T, ?>` in a `let`'s type takes the length from the value (`let names: list<string, ?> = ["a", "b"];` is a `list<string, 2>`). `v[i]` (the index checked), `v.len()` (a constant), `for x in v` and `==` work as on a list; `v[i] = x` sets an item in place in a variable or a record's field, where the list is. `push` and `pop` do not apply, and `?` is only a `let`'s (a parameter, field or result names its length).
- **Tuples:** `tuple<s32, string>`, values `(1, "a")`, and `(x,)` for one item. `t.0` reads an item (yel does not say how; this is the bootstrap's choice).
- **Unit:** `()` is the value that says nothing, and its type (`func(s32) -> ()`, `let u: () = ();`); a func without `-> T` returns it. There is no empty tuple (`tuple<>`, which WIT has not either). A case carrying nothing holds `()`: `ok(())` is `ok` and `Shape.dot(())` is `Shape.dot`, and `ok(())` or `ok(_)` matches it. A `result`'s side carrying nothing is still written `_`, as WIT writes it (`result<_, string>`).
- **`match`**: arms `pattern => value,` or `pattern => { … }`, the first that fits taken. A pattern is `_`; a literal (`3`, `-1`, `"bye"`, `'x'`); a constant; a case, its payload's pattern in parens (`some(ok(0))`, `dot({ x: 0, y })`); a record's fields' patterns (`{ x: 0, y: let y }`, a field alone its name's pattern, the fields left out any value); a tuple's (`(0, _)`); or alternatives (`1 | 2 | 3`, `circle(0) | square(0)`), which bind nothing. A name binds after `let` (`let k`, `let (a, b)`, `let { x, y }`) and inside a case's parens (`some(v)`); elsewhere it is a case of the type at its place, else a constant. `pattern if cond => …` takes the arm only when the guard holds too, its bindings in scope. Every match is exhaustive: the value's type less each arm's pattern (guarded arms left out), as sets of values, must be empty, and what is left names a value no arm fits (`the match has no arm for some(circle(_))`, `… for 3`, `… for "b"`). An arm's alternatives may bind (`for-stmt(x) | loop-stmt(x) => x.body`, `some(ok(n) | err(n)) => n`): the arm is one for each alternative, the same guard and body, each checked with its own bindings' types (so x may be a different record in each); a `let`'s alternatives bind nothing.
- **`const`:** `const LIMIT = 10;` or `const ORIGIN: s32 = 0;` names a literal (a number, `-` before one, a string, a char or a bool). A use is the literal, of the const's type when written (else typed where it is used, as a literal is), and a pattern compares with it.
- **Globals:** `let count: s64;` or `let label: string = "start";` at a module's top level: a value any func reads and assigns (a local of the same name hides it). No code of the program runs before `main` (or a component's first export): a global starts as its literal, or as its type's zero value: `0`, `false`, `""`, `none`, a list, map or set made empty, and a tuple, anonymous record or fixed-length list of such. A record has none (it is a reference, never null): hold it in an option, `none` until it is set. Each global is a root of the collector.
- **Visibility:** `@(private)` or `@(private="file")` before a declaration (a func, a type of any kind, a const, a global, a module) limits who may name it:
  1. Without one, whoever reaches it may: its package's files, and another package that includes its module.
  2. `@(private)`: its package's files only.
  3. `@(private="file")`: its own file only.
  4. Every kind of declaration alike, modules too: a private module is never included by another package, and its items are as private as it; a variant's cases are as visible as their type (`Type.case`, a bare case name).
  5. A declaration may not name, in its signature (a func's params and result, a record's fields, a variant's payloads, a global's type, an alias's target), a type fewer may name than may name it: `leak: func() -> Secret` with `@(private) record Secret` is an error. (Declared levels only: a package's top level, unreachable from another package anyway, is not a level.)
  6. WIT follows it: a reactor's (no `main`) visible modules are its exports, and a private module or func is never exported nor written into the component's WIT. There is no `export` keyword: what may be named outside is what is exported.

  All of it is one lookup (`checker.lookup`): every name a declaration is found by goes through it, and what may not be named from where it is written is not there; when nothing else is, the error says why and where (`func scale is private to its package (@(private))`, noting its declaration). `tests/vis-lib` holds each kind at each level, used from its own file, its package's other file and another package (`tests/visibility`); `tests/errors/visibility-*.yel` what may not be named.
- **Async:** `name: async func(…)` is WIT's async func, written the same: a func that may wait. `wait f(x)` waits for an async call (a bare call of one is an error saying which to write), `start f(x)` begins one and gives its `future<T>` (it runs while the starter goes on), `wait fut` waits for a future, `wait a | b` for the first done (its result a union of theirs: `let n: s32 =>` tells which), and `wait { a: x, b: y }` for all (an anonymous record of their results). `wait` is only in an async func (`main` may be one; a closure is not one yet); `start` is anywhere, a sync func's or a closure's too, since it never waits (the task runs once whoever started it waits, or an async export's call runs its tasks; in a program with neither, nothing runs it). An async func is a state machine (stackless): its frame holds its result and every local (on the heap, traced), each `wait` is a state, and its step goes on from where it waited, giving 0 (waiting) or 1 (done). A future is its frame. The executor is yel's standard library (`runtime/std/core/async/async.yel`): an async main's task, then each started task, a turn at a time (`yield-turn()` gives the others one); the runtime's C keeps the started tasks rooted. A program with no async func has none of it (nothing of it is reached). Tasks are woken, not polled: one that cannot go on parks, and what it waits for puts it back in the ready queue (a task once done wakes those waiting for it; `wait a | b` takes the one done first). `sleep(ms)` waits on a timer: when no task is ready, the reactor (the runtime's C) sleeps until the first one is due, so an idle program uses no CPU, and when nothing could ever wake a task, the executor says it is a deadlock. Natively, the WASI calls that would block wait on that reactor too, as a component's wait on its host: a file's reads and writes, its opening, its stat, making, removing and renaming are run on libuv's thread pool (the task parked until the call is done, another task running meanwhile), and stdin and sockets never block (a read, a write, an accept or a connect that would waits on the descriptor's watch, which wakes the task once it can go on). So a native program serves a TCP connection and goes on with its other tasks at once (`tests/tcp.yel`: a server and its client in one program). A race with a timer is a timeout (`match wait fetch(url) | sleep(1000) { let page: string => …, () => … }`).
- **Async across WIT (WASI 0.3):** a WIT `async func` is a yel async func: `wait monotonic-clock.wait-for(ns)` calls it async-lowered (`[async-lower]…`: returned at once, done; else its subtask joined to the call's waitable set, the task parked until the host's event says it returned). An exported `async func` is lifted with a callback (`[async-lift]…`): its call starts as a root, the executor runs that root's tasks (each call runs only its own), and it gives the host `EXIT` once done (its result by `[task-return]…`) or `WAIT` on its waitable set; the host's callback wakes the task the event is for and runs them again. No context slot is used (wasi-libc's P3 runtime keeps its stack pointer in slot 0): the runtime keeps which waitable is whose. An async main in a component waits on the host the same way (`waitable-set.wait`). Natively the same calls run on the runtime's C (`wasi-native.h`: a clock's wait is the executor's timer), and `sleep` is the clock's wait, so a component sleeps on its host. A `stream<T>` or a `future<T>` crosses as a param or a result, or inside one (a record's field, an option, a result, a tuple, a list's items, a variant's payload: `stdin.read-via-stream()` gives `tuple<stream<u8>, future<result<_, error-code>>>`), in an async func's call. The host's (an import's result, an export's param) is a yel stream the host writes: a read with no items left reads the host's end (`[async-lower][stream-read-N]…`, waited for when it blocks), its items lifted; a future, a yel future the host completes. A yel stream given the host (an import's param, an export's result) is pumped: a new pair, its readable end given, and a task of the call writing the stream's items to the writable end as they come (the items kept until the host has copied them), dropping it once the stream is closed; a future, written once it is done. An export's call goes on after its result is given (`[task-return]`) until its pumps are done. A host's stream given back to the host with none of it read here is given as it is (its end moves, nothing copied); one read in part is pumped, the rest read from the host as the host reads it. Each stream's and future's builtins are its func's, by its place in the func's type, depth first over the params and then the result (`[stream-new-0]squares`, …); the lift and lower helpers of a type holding them are made for each place. A local holding a stream or a future given a WIT func is moved (its end leaves the component). It must be one made here (a func's new value, or a part of one: `let (s, w) = stream-pair(8)`), not stored or captured before; and a use after, a give in a loop it is made outside of, or another name for it is an error when compiling (`out is moved to write-via-stream (its end leaves the component): it is used again at 8:5`; `compiler/effects.yel`). And where a local holding one is last used, the compiler lets its end go (`compiler/releases.yel`, on the IR): a host's stream read in part has its end dropped (its writer told no one reads: else stdin's future, say, never comes), a host's future not waited for has its end dropped, and a writer is closed (its reader sees the end). Only a local no one else has: bound by a `let` from a new value (or a part of one), not a parameter, not moved, kept, given back, captured or given a started call (whoever has one of those lets it go). A func only ever started (`start serve(connections)`, never waited for, called by the host or taken as a value) is the one that has its parameters: the caller gives a started call what it gives it, so such a func lets a parameter it never assigns go as it does such a local (`serve`'s listening stream, once it has taken its connection). The release goes after the statement that last uses it, and before each `return`, `break` or `continue` that leaves its block earlier; a read under way when it comes lets the end go once done. The runtime's async parts are three headers: `runtime/async.h` (every target's: tasks, queues, wakers, timers, streams between tasks), `async-native.h` (the timers' reactor) and `async-wasi.h` (the host's waits, events, and what crosses WIT).
- **Streams:** `stream<T>` (its reading end, WIT's) and `writer<T>` (its writing end): `let (lines, out) = stream-pair(8);` gives both, room for 8 items. `wait out.write(x)` waits for room (backpressure, as WIT's streams), `out.close()` ends it, `wait lines.read()` gives `some(x)`, or `none` once it is closed and read, and `wait for line in lines { … }` reads each in turn. Reading and writing are yel in the standard library (`runtime/std/core/async/streams.yel`), over a queue the runtime holds; no reactor is needed between two tasks.
- **Distinct types:** `type id = distinct u32;` is a type of its own, held as `u32`: no `u32` (nor a literal) is an `id`, nor an `id` a `u32`; `as` converts each way (`3 as id`, `i as u32`). `==` compares two, `<` orders them where their base is ordered, they show as their base, and they cross WIT as it. Ids that must not mix (a binding's, a local's) cost nothing at run time: the back end sees the base.
- **Maps and sets:** `map<K, V>` holds values by keys of any type, equal as `==` says (a string, a tuple, an option by its parts; a declared record or a list by itself), hashed to match (the compiler's hash for each key type); keys come back in the order they were set (`map-keys`), and `map-remove`, `map-len`. `set<T>` is a `map<T, ()>`: `s.add(x)`, `s.has(x)`, `s.remove(x)`, `s.items()`, `s.len()` (`runtime/std/core/collections/set.yel`).
- **Generators:** a func that yields gives back a `seq<T>`: `values: func(t: Tree) -> seq<s32> { … yield n; … }`, read with `for v in values(t) { … }`. A generator is a state machine as an async func is (its frame holds its locals, each `yield` a state): its call makes the frame and runs nothing; each turn of the `for` steps it to its next value, and a `for` that breaks leaves the rest unmade. A generator may read others (`for v in values(k) { yield v; }`); it does not wait (no `wait` or `start` in one), and a closure's body does not yield.
- **Statements:** `let` (with an optional type), `let` and a pattern every value fits (`let { x, y: down } = p;`, `let (n, label) = t;`, `let _ = f();`: a pattern a value may not fit is an error naming one, as a match's), assignment and `+= -= *= /= %=` (to a variable, a field, or a list's item: `xs[i] = v`, which is `set(xs, i, v)`), `return`, `for x in list`, `for i in a..b` and `a..=b`, `loop { … }` (its body again until a `break` or a `return` leaves it: what `wait for` and the executor's turns are; `loop` is a name where no `{` follows), `break` and `continue` in a `for` or a `loop`, and expression statements. An `if`, a `match` or a block that starts a statement is the statement: what follows its `}` is the next statement (`if c { … } -1` is an `if`, then `-1`), and in parens it is an operand (`(if c { a } else { b }) - 1`). A block that never gets to its end has no value of its own, so it is any type: one ending in a `return`, a `break`, a `continue`, or a `loop` no `break` leaves (`power-past: func(n: s32) -> s32 { let p = 1; loop { if p >= n { return p; } p *= 2; } }`, and a match arm `none => { break; }` where the others give a value).
- **C templates:** `c"if ({test}) { x = { 0 }; }"` is a string in which `{` starts an interpolation only before a name or `(`, so C's braces need no escape (the generator writes its C this way).
- **Expressions:**
  - integers (`42`, `0xff`, `0o17`, `0b1010`; `007` is 7), floats (`3.14`, `1e10`, `2.5e-3`, `inf`, `nan`), chars (`'a'`, `'\n'`, `'\u{1F600}'`), `true`/`false`, strings with WAVE's escapes (`\u{…}` included) and `{expr}` interpolation, WAVE's multiline strings (below), list literals `[a, b,]` and tuples (a list literal every item of which is a constant, its numbers, bools, chars, strings, records, tuples and lists of them, or a call of a func that only makes a record of its parameters given constants, is static data: copied when it is evaluated, each evaluation a list of its own and every list in it too, no code building it item by item);
  - by yel's precedence: `|| && == != < <= > >= | ^ & << >> + - * / %`, unary `-` and `!`;
  - calls, `x.f(a)` for `f(x, a)`, `xs[i]` for `get(xs, i)`;
  - `if`/`else` and `match` as expressions, and blocks, whose value is the last expression.
- **Multiline strings** are WAVE's. `"""` and a line break open one, and a line break, spaces and `"""` close it. Each line gives up as many spaces as come before the closing `"""` (an empty line has none to give), and the first and last line breaks are not part of the string. Escapes and `{expr}` work as in any string, and an error inside one is reported at its line and column in the file. A `"""` in the text is broken up by escaping a quote after the first (`""\"`); as in WAVE, `\"""` is an error.

  ```
  let text = """
      Hello, {name}!
        indented two
      """;           // "Hello, yel!\n  indented two"
  ```
- **Names** are kebab-case with yel's hyphen rule: `n-1` is one name, `n - 1` is a subtraction.
- **Types as sets** (`compiler/semtype.yel`): the checker's core is semantic subtyping: a type is the set of values it holds, a subtype a subset, and union, intersection and difference are set operations. Values are partitioned by kind (unit, bools, each number type, chars, strings, tagged products, and opaque types told apart by identity: a list, func, map or buffer, mutable and so invariant). A declared record, variant or enum is a nominal atom, held whole until a pattern looks inside and then opened one level, so a recursive declaration is opened only as deep as a pattern reaches. Match exhaustiveness and assignability use it: a value fits where a type is wanted when it is the same type or its values are a subset (`"get"` where `"get" | "post"` is, a `"get" | "post"` where a `string` is).
- **Type aliases, unions and literal types:** `type method = "get" | "post";` is WIT's alias syntax, and an alias is the type it names (no new type: a declared `record` or `variant` is one). `A | B` is a union and a literal is a type of one value (`"get"`, `3`, `-1`, `'a'`, `true`; an integer's is an `s32`). A union is never inferred: `let s = "get";` is a `string`, and a literal is its one value only where a union of literals is wanted. A union of one kind of value is held as that kind (`"get" | "post"` is a C `ystr`, so it widens to `string` for free). A union of kinds (`s32 | string`, `Item | string`) is a struct held by value: a tag and a field for each kind, apart (`{ int32_t tag; int32_t c0; ystr c1; }`, the others zero, so the collector only reads pointers). Where a value fits a type that holds it another way, the checker marks a conversion (`widen`) and the C calls one helper made for that pair (into a union, between unions, inside an option, a result or a tuple); reading a local the checker narrowed takes its kind's field. `x is s32` on a union is a tag compare, a match's literal, case, record or tuple pattern tests the tag of the kind it looks inside (one kind: a pattern two kinds could fit is an error), and `let n: T` matches by type (a typed binding: `let n: s32 => n + 1`), with what no arm fits named the same way (`no arm for let x: string`). A union shows (and interpolates) as the value of its kind.
- **Ranges:** an integer's or a char's values from one to another, as a type (`type percent = 0..=100;`, `type digit = '0'..='9';`, `1..6` for 1 to 5) and as a pattern (`10..100 => …`, `'a'..='z' => …`). The checker holds integers and chars as ranges (each type's whole range exact: a `u8` is `0..=255`, a char the Unicode scalar values), so a match covers a type by its ranges (`0 | 1..=9 | 10..100 | 100..=199 | 200..=255` is every `u8`, no `_`), and what is missing is named (`no arm for 101`). A range value is held as its base type: a literal where a range is wanted is checked when compiling (`101` is not a `percent`), arithmetic leaves the range (`p + 10` is an `s32`), and `as?` comes back in (`(p + 10) as? percent`). `x is 1..=3` is two compares; across WIT a range is its base type, checked when lifted. Floats have no ranges (NaN, -0.0 and no next value).
- **`as?`:** `x as? T` is an `option`: `some(x)` (as the narrower type) where `x is T` holds, else `none`. With `is`, it is the only way to ask whether a value is of a narrower type; nothing in yel throws for a type (`as` converts numbers, chars and bools, total, and refuses the rest when compiled).
- **Literal and union types across WIT:** an alias names the type at a component's boundary. Its string literals cross as a WIT `enum` (`type method = "get" | "post";` is `enum method { get, post }`; each string must be a WIT name), a union of kinds as a WIT `variant` with a case for each kind (`type value = s32 | string;` is `variant value { %s32(s32), %string(string) }`), and anything else (integer literals: `type level = 1 | 2 | 3;`) as its kinds' type. A literal or union type an export reaches (in records and variants too) that crosses as an enum or variant must have its alias (the error says how to write it). What the other side gives is checked when lifted, and a value that is not its type's traps: a literal type's value (`raise(7)` for a `level`), an enum's or variant's tag, an option's or result's tag, a `char` that is not a Unicode scalar value. `==` takes two types when one's values hold the other's.
- **`is` and narrowing:** `x is T` is a `bool` (it never fails; a test that can never hold is an error), compiled as the pattern of `x`'s type that `T`'s values fit (`m is "get"` is one string compare, `s is method` one per value). Where it holds, a local `x` is `x ∩ T`, and where it fails `x \ T`: in an `if`'s branches, after an `if` whose block leaves (`if m is "get" { return …; }`), on the right of `&&` and `||`, through `!`, and in a `match`'s arms (each sees what the arms before it left, a `let` of the whole value too). Narrowing is sound by keeping to what cannot change: a local the func never assigns (anywhere, closures included), and never inside a closure, which may run later.
- **Types** are checked before any C is made:
  - all of [WAVE](https://github.com/bytecodealliance/wasm-tools/tree/main/crates/wasm-wave)'s: `bool`, `s8` to `s64` and `u8` to `u64` (`int` is `s32`), `f32` and `f64` (`float` is `f32`), `char`, `string`, `list<T>`, `tuple<T, U>`, records, variants, enums, `option<T>`, `result<T, E>` (`result<_, E>`, `result<T>` and bare `result` leave a side out) and flags. `map<T>` is the bootstrap's own, keyed by strings;
  - numbers are never converted: `u32 + s32` is an error. A literal takes the type its context wants (`count == 0` for a `u32` count), and otherwise is an `s32` (an integer) or an `f32` (a float). A literal that does not fit its type is an error, but `-128` is an `s8`;
  - `< <= > >=` compare numbers, chars, bools and enums. `==` works on any two values of one type;
  - generic funcs `func<T>(xs: list<T>) -> T`, their type arguments inferred at each call; inside the func, `T` is only `T`;
  - a `let` without a type, and `[]` or `none`, take theirs from how they are used, so `let xs = []; xs.push(1);` is a `list<s32>`;
  - a record literal is the record its context wants, or else the one record with exactly its fields;
  - a func without `->` returns unit, and ignores its body's value.

  Errors are diagnostics, as rustc's (`compiler/diagnostics.yel`): the message, where (`--> file:line:col`), the source lines with the innermost expression at fault underlined `^^^` (and other places that explain it `---`, each with a label), then notes and help:

  ```
  error: out is used after it is moved
   --> cat.yel:8:5
    |
  7 |     let written = stdout.write-via-stream(out);
    |                                           --- moved here: write-via-stream takes its end (it leaves the component)
  8 |     out;
    |     ^^^ used here, after the move
    |
    = help: a stream or a future given a WIT func is the callee's: read what you need from it first
  ```

  A name not found (a local, a func, a field, a case, a flag, a module's or a resource's func) suggests one a few edits away (`= help: did you mean total?`). Colored on a terminal (`NO_COLOR` turns it off), plain otherwise. The lexer's, the parser's, the checker's, the effects' (readonly, moves) and the packages' errors are all diagnostics, and one run tells them all: each phase reports an error and goes on (the lexer past the character, the parser past the statement or declaration it is in, the checker with an error type that fits anything, so what a mistake made is not told again), and where a phase ends the errors found are shown in the order of their places, with a count, and the compiler stops; codegen never sees a program with an error. One error is told for each statement, and a file the lexer could not read gets no parser errors (they would be echoes). At 20 errors it stops at once (clang's `-ferror-limit`). A WIT package's own errors and a file that cannot be read stop it at once. A panic is the compiler's own fault. Every token, expression, statement, match arm and declaration keeps its span (start and end, line and column), and an expression inside a string's `{…}` keeps its place in the file.

  The C is typed from the checked types:
  - an `s32` is an `int32_t` (and so on for each width), an `f64` a `double`, a bool a `bool`, a char a `uint32_t` (its code point), a string a `ystr` (its UTF-8 bytes, by value), unit a `yunit`. Integer `+ - * / % << >>` wrap as WebAssembly's do (`y_add_s32` and the rest), a shift takes its count modulo the width, and dividing by zero stops the program;
  - a record is a pointer to a struct, and a variant a pointer to a tagged union. A case without a payload is one static, an enum is an `int32_t`, and flags are a `uint32_t` of bits. An option, a result and a tuple are structs held by value;
  - a list is a `ylist` of items of one C type, cast on access. A map is a `ymap`;
  - a generic func is compiled once for each list of type arguments it is called with;
  - a value is shown as WAVE, the Component Model's text for values: `{name: "a.txt", size: 12}`, `[ok(1), err("no")]`, `(3, 'z')`, `{read, write}`, `inf`, a label that is a keyword as `%ok`. In an interpolation, a string or char shows as its own text. The C funcs that show a value, and those for `==` on options, results, tuples and cases, are made for each type that needs them. `==` compares strings by their bytes, and lists, maps and records by identity;
  - a yel func's C name is `u_` and its name, apart from the runtime's `y_`.
  - a parameter may have a default, a literal or a directive (`word: string = "hello"`); a call leaves out the last ones that have one (`x.f()` too). Each parameter after one with a default has one.
- **Regex literals:** `/(\d{4})-(\d\d)/i` where a value starts (after a value, `/` divides). Each is compiled with the program: the compiler reads the pattern (a bad one is an error where it is written: an unclosed group, nothing to repeat, a range out of order, a back reference or lookaround, which are not compiled) and builds a matcher of its own for it, a backtracking machine whose states are a `match` on the instruction's number (the C a switch, the pattern in its code; its choices kept and undone by std's `regex.choose`, `save` and `back`), so nothing is parsed when the program runs. Its value is std's `regex` (`runtime/std/core/text/regex.yel`): `r.test(text)`, `r.find(text)` (a match: its text, start and end in bytes, its groups, `regex.group(m, name)` for a `(?<name>…)`), `find-all`, `replace` and `replace-all` (`$&`, `$1`, `$<name>`, `$$`), `replace-each` (by a func), `split`. Flags `i`, `m`, `s`; `.` and a class take a code point (UTF-8). `tests/regex.yel` checks it against outputs worked out apart from yel.
- **Async context:** a global marked `@(context)` (`@(context) let request: string;`) is each task's own: set in a task, it stays that task's across its waits whatever the others set meanwhile, and a task started takes its starter's as it is then; outside any task it is a global. The runtime keeps it so: the globals hold the values of the task being stepped, and the executor keeps each task's (a copy, traced) while another runs, so reading and writing one costs what a global's does, and a program with none pays nothing. std's `reactive` keeps its owner so: a task started under an owner adds its cleanups to it, even after it waits.
- **`YEL_ASYNC_TRACE`**, as `YEL_GC_STATS` is for the collector: `1` tells, on stderr, each task started (and by which), each time it parks and what it waits for (a task, a timer, a stream's items or room, a descriptor, a file operation, the host), and once it is done (how long it was stepped, in how many steps, how long it lived); at a deadlock, each task still waiting and on what; at the program's end, each task never done. `2` tells each step and each wake too. Unset, nothing is kept (a deadlock says to set it).
- **Keywords' words as names.** `if`, `else`, `match`, `for`, `in`, `return`, `break`, `continue`, `let`, `as` and `is` are keywords; the rest of yel's words (`record`, `type`, `module`, `enum`, `view`, `start`, `wait`, …) take their meaning only where they start what they name, so `record: func(…)` is a func named `record` (a `:` after the word makes it a declaration's name). Any keyword is a name written `%name`, as WIT writes one (`let %in = 3;`, `%match(x)`, a field `%type`), and a case's name before `(` or a member's after `.` needs no `%` (`Kind.return(x)`). A `%` right after a value stays the remainder (`a % b`, `a%b`).
- **Directives,** `#name`: what the compiler knows (attributes stay `@(…)`). `#file`, `#line`, `#column`, `#func` and `#location` (std's `source-location`: all four) are where they are written; as a parameter's default, `#caller-location` and `#caller-expression(param)` are the call's: its place, and the text of the argument given for `param`. `#embed("path")` is a file's bytes as a string (C23's `#embed`), read as the program is compiled: the path from the file's directory, or one `yelc --embed name=path` names, so a build can embed a file it makes (std:build's `a.embed(name, file)`, the artifact made again where the file changes). The directives may be a `const`'s value (`const MOTD: string = #embed("motd.txt");`).
- **Assertions and tests.** Core's `assert(condition)` stops the program where the condition fails, telling the call's place and the condition as written (`tests/defaults.yel:37:5: assertion failed: total * 2 == 7`), or the message given. `std:testing`'s `expect` module tells what it found: `expect.equal(got, want)`, `not-equal`, `holds`, `some`, `none`, `ok`, `err`, `contains`, `length`, `contains-text`, `near`, `fail`, and `snapshot(text)`: the runner loads the test's file's snapshots (`snapshots/<file>.snap` beside it) before the test runs, `expect.snapshot` compares the next one with what it got, a new one is written once the test passes, and one that differs fails with a line diff (`YEL_SNAPSHOTS=update` writes it instead). A func marked `@(test)` is a test: `yelc test <package> <out.c>` makes the package's tests a program (its own `main` left out) whose runner (`std:testing`'s `runner`) runs each in a process of its own (`std:process`'s fork: a failure ends only its test), those its arguments name if any, telling `ok` or `FAIL` for each and how many failed (its exit status 1 when any did). For a component (`--wit`, or a wasm triple) the runner is instead an export interface, `tests` (`names()`, and `run(name)`), the package's other modules kept its own: `tools/test-component.sh <package> [names]` builds it (`WASI_SDK`) and calls `run` for each test on a fresh instance (`wasmtime --invoke`), so a failure ends only its test there too, told as the native runner tells it. Any other build checks the tests and leaves them out. Tests may also live in a package's test files, `<name>.test.yel`: a package has them only where it is tested or checked (`yelc test`, `yelc check`, the language server), so what they include (`std:testing`) is never a build's, nor an including package's. `expect.equal` compares by `==`, else by what each shows (a list's items, a map's entries), and `expect.same` by `==` alone (a list's or a resource's identity). std tests itself this way: `yelc test runtime/std/core` (its core: number, text, buffer, map, format) and `yelc test runtime/std/encoding` (hex, base32, base64, uuid, json), each run by `./bootstrap.sh`, also under GC stress. The compiler tests itself the same way: `yelc test compiler` runs `compiler/*.test.yel`, whose tests build a small program written in the test (a C template, `c"..."`, its blocks' braces no interpolation) as IR in memory (`analysis.lower(path, text)`: the file an overlay, loaded with the prelude and std's core, checked, and built by `gen.lower-program` as far as its releases, nothing optimized; else the problems that stopped it) and assert what the passes made of it: `escape.test.yel` the flow's groups, each func's summary (parameters written, kept, given back; a new result) and the records it keeps on the stack; `releases.test.yel` which ends each func lets go and where (a started func's own parameters, and those its caller still has); `analysis.test.yel` checks one as the language server does (`analysis.check`), and what a name there names and the signature a hover shows of it (as its declaration writes it: its type parameters, each default as written, its types named as an include names them). `std:process` is the processes themselves: `process.fork()` (a child that runs on from there, its memory a copy), `process.wait(child)` (the code it ended with, or the signal), `process.run(command, arguments)` (a program run and waited for, looked for on `PATH`, its streams and environment this process's: `posix_spawnp`), `process.run-with(command, arguments, dir, environment, output)` (variables more, its output to a file), `wait process.run-async(…)` (the same, its task waiting while the others go on: libuv's `uv_spawn`), `process.target()` (the target triple), `process.end(code)`.
- **Builds.** A project's build is a program, `build.yel` beside what it builds (no `build.sh`): its `main` hands `std:build`'s `build.run` a func that declares what the project is made of, and `yelc build [step]... [-Dname=value]... [--help]` finds the nearest `build.yel` (here or above), compiles it once into a runner (kept in the project's `.yel-cache` by a key of `build.yel`, `std:build` and the compiler) and runs it: what was declared runs as steps, each after those it depends on, each once. An artifact is yel compiled: `b.component(name, root)` (a WASI 0.2 component: yelc, then the WASI SDK's clang, `-Dwasi-sdk=<dir>` or `WASI_SDK`), `b.executable(name, root)` (yelc, then `cc`), `b.test(name, root)` (`yelc test`'s runner); its WIT and yel packages are its `wit(dir)` and `include(dir)`. `b.install(a)` puts it in the prefix (`yel-out`, or `--prefix <dir>`/`-p <dir>`: `<name>.wasm`, `bin/<name>`) as a step of its own and one `install`, the default step, runs (`b.install-file(path, to)`, `b.install-executable(path, to)` a file); `b.run-artifact(a)` runs one (its arguments those after `--`); `b.command(arguments)` runs a program (`.named(name)` tells it by name), and a run or a command checks what it does: `set-environment(name, value)`, `expect-output(file)` (what it prints, its standard output and error, must be what the file holds), `expect-exit(code)`; `b.system-libraries()` are what an executable for this system links; `a.wasm-opt(flags)` runs Binaryen's `wasm-opt` on a component's core module before `wasm-tools` makes it the component (its WIT embedded first), `a.embed(name, file)` gives `#embed(name)` a file (one a step makes too), `a.compiler(yelc)` and `a.c-flags(flags)` build an artifact with another yelc and other C flags; a build program declares from what is there (`b.entries(dir)`, `b.find-program(name)`, `build.variable(name, otherwise)`); `b.step(name, description, steps)` is one `yelc build <name>` runs, and `--help` lists them and the options (`b.option(name, description, default)`, `-Doptimize=size|speed|none` by `b.optimize()`); an unknown step or option is an error. Each artifact is made in `.yel-cache/o/<key>`, the key a hash of all that goes into it (its kind, settings, every `.yel` and `.wit` under its root and the directories it includes, the compiler's bytes, the runtime's and std's sources), so one made before is not made again and a changed source, option or compiler makes it anew. A step may make files: a command's output (`step.output-file(name)`, `step.output-dir(name)`: its path given to the program as an argument, in the step's own directory of `.yel-cache`) is a path the rest of the build takes as it takes the project's (an artifact's root, its `wit` and `include`, another command's argument or `input`, `b.install-file(path, to)`: each a `string | generated`), and what takes it runs after the step that makes it, with no `depend` written. A step that makes files is made once for what goes into it (its program, its arguments, every file its `input`s name), so a generator runs again only where what it reads changes; one that makes none runs each time. `b.write-files()` (`add-file(name, content)`, `directory()`) makes files the build program writes itself; `b.run-artifact(tool)` runs the project's own tool, and takes outputs too. Commands run in the project's directory (`yelc build` runs the runner there: `process.run`'s `dir`). The steps run as tasks, each once what it depends on is done, at most `-j<n>` programs at once (the cores by default); a failed step fails those that depend on it and no others, and `--summary` tells how many ran and failed and the slowest. `tests/build-system` is std:build's own test. yelc finds its runtime from its own place (the directory above its binary's, or `YEL_HOME`), so it runs from any directory: without a prelude given and no `runtime/` here, it takes its home's. `examples/build.yel` builds the examples, and `build.yel` the compiler itself (its stages); `apps/cloud-yel/build.yel` (meshx-shell) is one outside the repository.

  Memory is garbage-collected, by one collector in C (`runtime/yel.c`) that works the same on native and on wasm (linear memory):
  - precise and non-moving, mark and sweep. A string's bytes, lists, maps, records and variants are heap objects, each with a one-word header naming its trace (the C func that marks the pointers it holds). The compiler makes a trace for each record and variant, and a scan for each type a list or map holds;
  - small objects live in 64 KiB pages of 24 size classes, large ones in pages of their own. A page table finds the object any address points into, so a substring's pointer into the middle of a string keeps it alive;
  - the roots are slots, as in TinyGo: a func whose locals hold pointers has a frame of slots (`void *ys[n]`), and each pointer a local takes is copied into its slot. The collector walks the frames, so it can run inside any allocation, in the middle of a call, on wasm as on native. A local stays in a register, as the collector never moves what it points to;
  - a collection runs when the heap has doubled since the last one left it (quadrupled, when that one freed less than a quarter), and not below 4 MiB (`YEL_GC_MIN_MB`). One call that makes 2 million records keeps its heap under 4 MiB, on native and on wasm under a 64 MB cap;
  - `YEL_GC_STRESS=n` collects every n allocations and fills freed memory with `0xAB`, so a pointer the C does not keep in a slot shows. `./bootstrap.sh` runs every test with n = 1, and the compiler compiling itself with n = 100 (and, with `WASI_SDK` set, as wasm under wasmtime with n = 50): each must print, or make, exactly what it does without. `YEL_GC_STATS=1` reports the collections at exit, `YEL_GC_STATS=2` each one.

  The back end works on an IR (`compiler/ir.yel`), one file for each job (`codegen`, `inline`, `escape`, `render`). A func is one tree of nodes, each its kind (`const`, `local`, `assign`, `bin`, `un`, `convert`, `load`, `store`, `if`, `loop`, `break`, `continue`, `block`, `return`, `unreachable`, `call`, `alloc`, `make`, `list-get`, `interp`), its type, and its effects (bits: reads memory, writes memory, calls, assigns). The constructors fold as they build (an `if` on a constant, a `!` of a `!`); nothing lowers the tree again before it is rendered, and one walk (`nested`, `operands`, `flatten`) serves every pass. Where yel differs: an operand is pure, since a node that calls or reads memory is put in a local where it is met, so a pointer live across a call is in a local the collector's slots see. `render` writes a body up to its first terminator, and a label only where a `goto` names it. Between codegen and render (`opt`):
  - **roots:** which funcs can collect (a fixed point over calls; the runtime's funcs that never allocate are listed), and each local's live range (loops extend it), so a local has a slot only when it holds pointers across a point where a collection may run. A func needing none has no frame. Compiling the compiler, that halves the slots' stores and takes 13% off its `-Os` build;
  - **escape analysis:** a func's locals in groups that may share a value, and whether each group's value leaves the func (returned, stored in a field or a new record, case or list, kept by the runtime, or passed to a param that escapes, found for every func by a fixed point over a worklist). A record whose group never escapes, all of it made in the loop the record is made in, is a struct on the stack, traced from the frame. In a loop over vectors that makes 150 million records the collector never runs (0.01 s, against 1.19 s and 762 collections without);
  - **inlining,** where a func returns a record it makes, so that record can stay on the caller's stack: `--opt size` (the default) inlines only a func called once (then dropped) or tiny, and adds 0.3% to the compiler's wasm; `--opt speed` inlines up to 40 statements; `--opt none` neither inlines nor places records.

  Compiling itself, typed C was about twice as fast as the old dynamically tagged `yv` C: 12 ms against 24 ms, with 2.5× fewer instructions and 56% less memory. With all of WAVE's types, the compiler is a third larger and compiles itself in 17 ms.

The compiler itself is written this way. Its syntax is `Expr`, `Stmt` and `Decl` variants with a record for each shape, and the parser and the generator are records, dispatched with `match`.
